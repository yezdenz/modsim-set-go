# Preserve the requested presentation

The user's designated template is the design authority. Keep its existing font families, sizes, colors, emphasis, alignment, paragraph spacing, borders, shading, headings, cover, and question wording. Reuse the local answer formatting for inserted text.

Do not import a formatting convention from another course or workflow without authorization. In particular, do not add a default first-line indent, justification, new title design, or global font change merely because a different repository uses it.

## Answer style

Write concise, natural explanations that connect a result to its meaning. Use actual numbers where helpful. Avoid canned introductions, inflated language, fabricated personal experience, and claims of understanding or independent testing that have not been established.

Use short bullet explanations below a result image only when they add information. Keep them inside the intended answer area. Do not repeat every number already legible in the image.

Distinguish a simulation estimate from an exact probability. State a negative expected value as an average loss per game and identify the stake. Keep rounding consistent across the report.

## Deliverable formats

If the user requests DOCX only, deliver DOCX only. Do not replace it with PDF or include additional final formats without a reason grounded in the task. Temporary renders used for internal layout review are not additional deliverables; keep them private and out of the handoff.

A separately requested declaration has its own format and requirements. Do not assume the assessment's DOCX-only preference forbids a separately requested declaration PDF, or that the declaration request authorizes converting the assessment.

Keep AI-use statements out of the assessment body when the user wants a separate declaration. Maintain truthful disclosure records and flag any conflict with an explicit rubric requirement rather than silently concealing it.
