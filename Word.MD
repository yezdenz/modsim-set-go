# Complete the exact Word template

Create a working copy from the exact file the user designated. Keep the original unchanged. Do not start from a blank document, substitute a redesigned report, or reuse an earlier self-designed report as the source.

Inventory the cover, body, tables, headers, footers, sections, images, styles, numbering, fields, comments, tracked changes, and embedded objects before editing. Identify the answer slots and permitted additions. Inspect hidden content without deleting it.

## Edit only the intended areas

Fill the blank answer cells and insert the requested images. Reuse the template's local paragraph and run properties. Preserve existing text, metadata already completed by the user, and all unrelated package parts.

Use inline embedded pictures, not external image links or floating overlays. Keep aspect ratios and size images to the actual usable cell width. Account for margins, spacing, and borders. Never let an opaque image mask a table rule or extend beyond its box.

Adding rows changes document structure. Do this only when the user requests it or an existing task instruction clearly authorizes it. Preserve the column grid, border style, heading colors, and surrounding design. Follow [Tables.MD](Tables.MD) for the standard requested evidence layout.

For small edits, prefer a targeted document-package patch where supported. If a document library rewrites the package, verify that unrelated styles, relationships, media, headers, footers, and objects have not disappeared or changed. Do not claim byte identity for a modified DOCX container.

## Render and review

Render the actual final DOCX and inspect every page. Check clipping, overlap, missing glyphs, image sharpness, cell boundaries, orphaned headings, split result/code pairs, blank trailing pages, and header/footer placement.

Preserve readability instead of shrinking all content to keep an old page count. Additional requested evidence may require more pages. Keep a result with its following code row where practical, and keep the final expected-value heading, computation, and evidence together.

If the renderer is unavailable, diagnose the specific limitation and use a supported isolated fallback. Do not control the user's live Word session or claim visual verification from text extraction alone.

Reopen the saved file. Confirm images remain embedded and the original template remains unchanged. For a small follow-up, edit the latest deliverable so earlier accepted changes are retained.
