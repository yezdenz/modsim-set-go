# Deliver the final work

Hand over the latest verified files in the user's requested format. A link to an earlier version is not a final handoff merely because its filename looks similar.

## Final reconciliation

- The exact requested template was used and the source remains unchanged.
- All questions, numeric answer rows, model code, result images, and requested evidence rows are present.
- Images fit their cells and remain readable; any source line numbers match the final script.
- The final script runs in the declared environment, computes the reported values, and prints the requested compact blocks directly in the Command Window.
- Reported probabilities, expected value, stake, counts, and sample sizes agree across files.
- Requested captions were removed and no unwanted AI disclosure or extra report sections were added.
- The actual final document was visually reviewed, including page breaks, code/result pairs, and the final EV section.
- Any declaration accurately records the AI contribution and does not claim unsupported signatures, attachments, or student verification.
- The requested file types and naming are respected. Private QA renders and build files are excluded.

Use a package only when requested or useful within the authorized scope. If the script changes after a ZIP is created, update the ZIP or explicitly retire the old package. Reopen the final package and compare its script and document with the latest approved files.

Never bundle the original assignment, private declaration, conversation, personal identifiers, or unrelated evidence into a public repository. Before a workflow publication, inspect the exact staged file list; use explicit paths instead of adding the whole school-project directory.

## Handoff message

Provide a brief outcome and links to the actual final files. Mention a material limitation or remaining user step plainly. Distinguish a completed draft from a signed declaration, a local commit from a published repository, and a prepared submission from an uploaded one.

For GitHub publication, verify the account, repository URL, visibility, remote branch, and published commit. A local repository or failed push is not publication. Authentication failures should leave a prepared, reviewable local deliverable and an exact access step, without requesting credentials in chat or evading organizational restrictions.
